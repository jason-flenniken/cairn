## Rules

- After any change in `plugins/cairn/cli/src/`, run `npm run build` and commit `plugins/cairn/dist/cairn.mjs` with it. `plugins/cairn/bin/cairn` runs the bundle, not the source.
- Raise `version` in `plugins/cairn/.claude-plugin/plugin.json` for any push users should get. Installs are cached by that version.
- Keep the CLI free of runtime dependencies. `yaml` is a dev dependency that esbuild bundles in (`package.json`).
- Keep `plugins/cairn/types/index.d.ts` free of `import`, or `claude plugin validate plugins/cairn` rejects it.
- Run `npm run typecheck && npm test` before shipping, and `claude plugin validate plugins/cairn` after manifest or type changes.
- Keep `bin/cairn` a thin shell wrapper that runs `../dist/cairn.mjs` (`plugins/cairn/bin/cairn`).

## How it works

The CLI is TypeScript under `plugins/cairn/cli/src/`. `npm run build` uses esbuild to bundle `main.ts` into one file, `plugins/cairn/dist/cairn.mjs`, targeting Node 20 as an ES module. The bundle is committed because people install the plugin straight from GitHub and there is no build step on their side. `plugins/cairn/bin/cairn` is a two-line shell script that runs the bundle with `node`.

The repo is a marketplace. `.claude-plugin/marketplace.json` lists one plugin, `cairn`, whose source is `./plugins/cairn`. Users install it from GitHub as `jason-flenniken/cairn`. Claude Code keeps a cached copy keyed by `version` in `plugins/cairn/.claude-plugin/plugin.json`, so a push that leaves the version alone never reaches them. The CLI reads that same version at run time (`pluginVersion` in `cli/src/util.ts`).

`npm test` runs the CLI tests with `node:test`, which runs the `.ts` files directly against `cli/src/`, then `npm run test:mod`. The mod script copies `.claude-plugin/`, `hooks/` and `types/` to a temp folder and runs `claude plugin test` there, so it needs the `claude` CLI on PATH. It does nothing if there are no mod tests. `npm run typecheck` runs `tsc` on the CLI.

The repo's own docs: `README.md` is the user-facing spec, `CLAUDE.md` guides agents working here, `docs/design.md` is the original design history (some names in it are out of date), and `docs/superpowers/specs` and `docs/superpowers/plans` hold design notes and implementation plans. `dogfood-docs.test.ts` and `install-doc.test.ts` check some of these docs.
