## Rules

- Every approval and level change needs proof from the user. The CLI check is the real control; the mod's deny-list is best effort. `cli/src/proof.ts:94` (`humanProof`), `cli/src/shared.ts:54` (`requireHumanProof`).
- The mod's one-time proof is spent on a match and put back on a mismatch, and only one concurrent caller can claim it. `proof.ts:62` (`secretMatches`).
- Read `CAIRN_APPROVER` once, then delete it from the environment. Commands the plan's config runs never see it. `proof.ts:98`, `shared.ts:110`.
- `--human` works only at a real terminal, with the plan slug typed. `proof.ts:101-105`.
- Only the secret's SHA-256 is stored on disk. The secret itself lives only in the mod's memory and is replaced after every use. There are no grant files. `hooks/mod/approve.ts:104` (`rotate`).
- Refusals come before the proof is spent. `cli/src/commands/level.ts:12`.
- The mod denies the model: running `cairn approve` or `cairn level`, setting `CAIRN_APPROVER`, writing `state.json`, `STATUS.md` or `.git/cairn/`, and wrapping cairn in a pty. `hooks/mod/guards.ts:34` (`bashVerdict`), `guards.ts:433` (`pathProtected`).
- Keep the plan-file guard covering both `docs/cairn/plans` and the legacy `docs/sdlc` plans folder. `guards.ts:423`.
- An answer approves only if the question is tagged for this plan and stop, the CLI reports the stop ready, and the label reads as approving. `approve.ts:52` (`isApproveLabel`), `approve.ts:88`.
- Approvals and level changes never ride an override. `hooks/NOTES.md` ("Menu approval and overrides").
- The mod counts as active only when its heartbeat is under 10 s old. If you change the heartbeat format, update `proof.ts:107` and `hooks/NOTES.md` together.
- Approval refusals keep naming the three legitimate routes: the menu, terminal `--human`, and the pane. `shared.ts:60-70`.

## How it works

Two halves meet at one check. In the CLI, `proof.ts` decides whether a command comes from the user. `cairn approve` and `cairn level` call `requireHumanProof`, which accepts either the mod's one-time secret or a typed-slug `--human` run at a terminal. If neither is present it refuses and lists the legitimate ways to approve.

In the mod, `approve.ts` watches the user's answer to a tagged approval or level menu. When the answer reads as approving, the mod runs the CLI itself with a fresh secret in the child's environment and stores the secret's hash under the git common directory. The pane's Approve button follows the same path. `approval.tsx` draws the pane card. `heartbeat.ts` writes a timestamp every 2 seconds so the CLI knows the mod is running.

`guards.ts` is the mod's second line. It hooks every Bash call and path-using tool call, including subagents', and denies the spellings that would let the model approve or edit state itself. Details of formats and exact deny cases are in `hooks/NOTES.md`.

## Gotchas

- 2026-10-20: The engine has no way to close an open chat approval question, so the mod answers it early when the pane approves.
- 2026-10-20: Approval tests once read results before the hash file was written.
- 2026-10-20: The Bash guard once denied heredocs, inline reads and `decide` prose that only mentioned the words. It now denies writes, not mentions.
