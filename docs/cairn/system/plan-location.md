## Rules

- The current git branch decides which plan a command acts on: `feature/<slug>`, `fix/<slug>`, legacy `sdlc/<slug>`, and task branches `task/<slug>/<task>` (`plugins/cairn/cli/src/locate.ts:104`).
- A hand-made branch is not a plan unless it matches the branch recorded in the plan's `state.json` (`locate.ts:130-150`). Legacy `sdlc/` branches are always accepted.
- Plan folders are `<YYYY-MM-DD>-<slug>`, dated by the local start date, not UTC (`locate.ts:27`). Tests depend on this.
- Folder lookup prefers the dated name and falls back to the undated one (`locate.ts:44`).
- A worktree folder is the branch name with `/` replaced by `-` (`locate.ts:26`).
- State is read and written in the plan's own worktree. A branch with no worktree is read with `git show` (`locate.ts:76`).
- Legacy `docs/sdlc`, `.sdlc` and undated folders must keep resolving. Nothing new is written to them (`plugins/cairn/cli/src/paths.ts:2-6`).
- Every CLI git call runs with auto gc and maintenance off (`plugins/cairn/cli/src/git.ts:11`).
- Pass any branch or base name from `state.json` through `safeRef` before handing it to git (`git.ts:86`).
- `cairn migrate` checks every clash before moving anything, and removes only empty legacy folders (`plugins/cairn/cli/src/commands/migrate.ts:52-67`).
- Close comes before merge. A merge is judged from the PR state or local ancestry, ignoring commits that touch only the plan folder (`git.ts:137`). This is display only; nothing gates on it.

## How it works

Every command starts in `context()` in `locate.ts`. It finds the repo top, lists worktrees with `git.ts`, reads the current branch, and turns the branch name into a plan slug (and a task name for task branches). It then checks that the branch really is that plan's recorded branch. If so, it points at the plan's worktree and the plan folder inside it.

The plan folder lives under `docs/cairn/plans/`. `resolvePlanDir` looks for `<date>-<slug>` first, then the old bare `<slug>`, and tries the legacy plans root under `docs/sdlc` after the new one. It can read from a checkout or from a committed branch tree, so old branches still find their records through the main checkout.

`cairn new` (`commands/plans.ts`) creates the plan and its branch. `commands/fix.ts` runs the fix fast lane, and `commands/migrate.ts` moves old `.sdlc` and `docs/sdlc` layouts to the new names. `paths.ts` holds the folder names, and `git.ts` wraps git calls, including merge detection.

## Gotchas

- 2026-10-20: Background git maintenance caused about one in three "invalid object" test failures. Auto maintenance is now off for CLI git calls.
- 2026-10-21: Git forbids `feature/x` and `feature/x/task` together, which is why tasks use `task/<slug>/<task>`.
- 2026-10-21: Looking up a plan by name alone mistook a hand-made branch for a plan. It is now keyed on the recorded branch. A hand-made `task/<slug>/x` on a merged plan can still be mistaken (open).
- 2026-10-21: Renaming plan folders on main hid old records. They now resolve through the main checkout.
- 2026-10-21: Dated-folder tests computed "today" in UTC and failed every evening.
- 2026-10-21: A base-branch name starting with `-` could inject git options. `safeRef` now rejects it.
- 2026-10-20: A fix-repro timeout cannot kill child processes when `setpgid` is refused.
