## Rules

- Never start two tasks together when their file scopes overlap (`plugins/cairn/cli/src/ready.ts:31-33`, `glob.ts:27`).
- Keep `scopesOverlap` conservative: when unsure, it says "overlap" (`glob.ts:27-37`).
- Scopes use only `**`, `*` and `?`. There is no brace support (`glob.ts:2-17`).
- A re-plan keeps each surviving task's progress, including its start commit, and refuses to drop a task that already started (`plan-parse.ts:130`, `commands/planload.ts:22`).
- A plan loads only if `plan.md` parses, has no `blocked_by` cycle, and every PRD requirement is covered or listed as deferred (`plan-parse.ts:84-93`).
- `blocked_by` may point only to the same or an earlier phase (`plan-parse.ts:81-82`).
- Approving the plan needs `planHash` to match the current `plan.md` (`commands/stages.ts:150`, set at `planload.ts:24`).
- Task branches are `task/<slug>/<task>` (`locate.ts:21`).
- Task start, step and done refuse unknown tasks, and step and done refuse tasks that are not running (`commands/tasks.ts:61`, `98`, `114-115`).
- Task done needs a clean worktree, at least one commit, the branch merged into the plan branch, and passing tests (`commands/tasks.ts:145-150`).

## How it works

`plan.md` holds a fenced YAML block tagged `cairn-tasks`, under `## Phases`. It lists phases, and each phase lists tasks with an id, a name, the requirements it covers, what blocks it, the file globs it may touch (`scope`), a complexity, and an optional risky flag.

`cairn plan load` reads `plan.md` and the PRD and runs `parsePlan`. Any problem is listed and nothing is saved. On success the phases and tasks go into `state.json`, and a hash of `plan.md` is stored. Loading again once the plan is past the planning stage is a re-plan: it needs `--replan`, merges progress from the old tasks, and asks for approval again.

`cairn ready` runs `readySet`. It looks at the current phase and picks pending tasks whose blockers are done. It skips any task whose scope overlaps running work or a task just picked, and stops at the configured parallel cap.

`cairn task start` makes the task branch and a worktree next to the plan's, then runs the repo's setup command. `task done` checks the work, and only then marks the task done, removes the worktree and deletes the branch. Edits outside the task's scope are logged as drift instead of blocking.

## Gotchas

- 2026-10-20: a re-plan used to drop each task's start commit. Re-plans now keep it. If you add a field to a task, add it to `mergeProgress` too, or re-plans will lose it.
