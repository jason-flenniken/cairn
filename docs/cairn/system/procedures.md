## Rules

- Run `npm test` after any wording change in `procedures/`, `skills/`, `templates/` or `references/`. Doc tests pin headings (`## 5.`) and phrases; update the assertion on purpose. (`cli/test/procedures.test.ts`)
- Write user-facing text per `references/reporting.md`: outcome first, plain words, no internal ids or machinery nouns.
- Keep skills thin. Each lists every `cairn` subcommand it needs by name in `allowed-tools`, never `cairn:*`, and never `cairn repro`. (`cli/test/skills.test.ts`)
- Keep template headings equal to `PRD_SECTIONS`, `PLAN_SECTIONS` and `RECORD_SECTIONS`. (`cli/test/templates.test.ts`)
- Give every subagent dispatch an explicit model tier. (`references/model-tiers.md`)
- The orchestrator stays at the repo root and runs `cd <plan worktree> && cairn …`. Subagents edit and commit only in task worktrees, and never touch `docs/cairn/`. (`procedures/execute.md`, `agents/implementer.md`)
- Label review findings Critical, Required, Optional, Nit or FYI. Critical and Required are fixed before merge; Optional and Nit become follow-ups. (`agents/task-reviewer.md`)
- Review every task on five axes, and add the security reviewer for risky tasks. (`references/model-tiers.md`, `references/levels.md`)
- Keep the discover interview's order: guess and confidence, goal questions one at a time, implications, decisions, read-back card that needs an explicit yes. (`procedures/discover.md`)

## How it works

`cairn next` reads the plan's stage and step and prints the path of a procedure file. `nextFor` picks the name and `procedurePath` in `cli/src/commands/status.ts` joins it onto `procedures/`. The agent then follows that file. With no plan, it points to `new` or `status`.

Skills (`skills/*/SKILL.md`) are slash-command wrappers. They allow a fixed set of `cairn` commands, call `cairn`, and follow the procedure it names. The real instructions live in `procedures/`, one file per stage or action.

Agents (`agents/*.md`) are the subagents: implementer, task-reviewer, security-reviewer, branch-reviewer, acceptance-checker, recorder, challenger and others. `references/model-tiers.md` says which model each runs on: simple tasks on haiku, standard on sonnet, complex on opus, the branch reviewer on opus. It escalates one tier on evidence.

`references/levels.md` defines MVP, Standard and Polished. The level sets how much effort each stage spends, such as the interview length, per-task review, and the record. Security and secret-scan floors stay at every level.

The doc tests read the markdown itself. They check procedure headings and phrases, skill allow-lists, and that template headings match the section lists in `cli/src/sections.ts`.

## Gotchas

- 2026-10-21: builders repeatedly committed in the wrong worktree and the commit had to be moved to the task branch. The brief must name the worktree and the implementer must confirm its branch. (sharper-interview-and-review)
- 2026-10-21: the worktree guard parses heredoc text like arguments. Pass long text through `--file` or `--note-file` (`references/cli.md`).
- 2026-10-21: when dogfooding, the installed plugin predates the plan under test, so the procedures a session follows can lag the ones in the repo.
