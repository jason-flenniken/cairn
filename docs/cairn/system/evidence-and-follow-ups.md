## Rules

- A review with blocking findings cannot be recorded as pass. `plugins/cairn/cli/src/commands/evidence.ts:39`
- Direction evidence is accepted only when the scorecard parses and has a row for every requirement the phase covers. `plugins/cairn/cli/src/commands/evidence.ts:15-22`
- The on-track verdict comes from the CLI's fixed scorecard, never from the agent's own word. Red blocks phase approval; yellow can be approved. `plugins/cairn/cli/src/direction.ts:60`
- A re-plan or a later code commit invalidates the verdict, which is stored with the commit it was computed at. `plugins/cairn/cli/src/commands/evidence.ts:24`
- At most 5 follow-ups stay open per plan. One declined twice or older than 60 days expires. `plugins/cairn/cli/src/commands/suggest.ts:15-18`
- Failing tests block through the shared tests check. At MVP level they become one hardening item per command instead. `plugins/cairn/cli/src/shared.ts:148-158`
- Review findings are labelled Critical, Required, Optional, Nit or FYI. Critical and Required are fixed before merge; Optional and Nit become follow-ups. `plugins/cairn/references/review-checklist.md`
- The post-edit hook logs out-of-scope edits as drift until `cairn drift ack`. Cairn's own files are never counted. `plugins/cairn/cli/src/commands/hooks.ts:70-94`
- The session-start hook must never throw. The memory index is built inside a try/catch. `plugins/cairn/cli/src/commands/hooks.ts:23-28`

## How it works

Evidence is how a plan proves each stage. `cairn evidence verify|review pass|fail` (`commands/evidence.ts`, `cmdEvidence`) records the result, a note, and a blocking-finding count on the plan's state, and logs it. `cairn evidence phase` runs the direction check for one phase: it reads the report file, parses the `cairn-direction` scorecard in `direction.ts`, and stores a green, yellow or red verdict with the commit it was computed at.

The post-edit hook (`hookPostEdit` in `commands/hooks.ts`) watches edits during a task. An edit outside the task's file scope is added to the plan's drift list and logged. `cairn drift ack <path>|--all` marks entries as reviewed. Edits to cairn's own folders are skipped.

Follow-ups live in `commands/suggest.ts`. Review and hardening findings, and failing test suites at MVP level, are pushed as suggestions. They can be closed, merged into another, declined, or expire. `cairn suggest` lists and manages them, and a plan may leave at most five open when it closes. The session-start hook in the same `hooks.ts` prints the plan summary and, when area docs or decisions exist, the memory index.

## Gotchas

- 2026-10-21: A failing suite is open work tied to its test command; a later passing run of that command resolves it, so the same command must be used each time.
