## Rules

- At close, every area doc whose `paths` cover a changed code file must have been updated on the plan branch, or skipped with `cairn area skip <id> --note` (`cli/src/commands/memory.ts:29`, `:70`).
- Changed code that no area covers also blocks close, unless `cairn area skip --uncovered --note` is used. Give every new code path an area glob (`commands/memory.ts:16`).
- With no area docs at all, close only warns and suggests `/cairn:map` (`commands/memory.ts:40`).
- Cairn's own files (`docs/cairn`, `.cairn`, legacy roots, `.claude`) are left out of the changed-code check.
- Never hand-edit `## History`. It is generated under `HISTORY_MARK` and overwritten (`cli/src/memory.ts:11`, `:48`).
- Keep `publishDecisions` idempotent per plan and question (`cli/src/decision-log.ts:107`).
- `loadAreas` and `loadDecisions` report or skip broken files and never throw (`cli/src/areas.ts:31`).
- Compute the session index live. Never store it, and keep it to 60 lines (`cli/src/memory.ts:109`).
- A failure while writing memory at close becomes a warning, never a failed close (`commands/memory.ts:117`).
- Records must meet their section lists and word budgets (`cli/src/sections.ts:49-53`).

## How it works

Each area of the system has a doc at `docs/cairn/system/<area>.md`. Its frontmatter lists `paths`, the files it covers. The doc says what must stay true, how the area works and what has surprised people. Plan folders stay as the append-only record of why things changed.

When a plan closes, cairn compares the plan's changes with the area paths. A covered area whose doc was not touched blocks close until the doc is updated or skipped with a note. Changed files that no area covers block it too. A repo with no area docs only gets a warning.

Decisions are logged in the plan as before. A decision marked `cairn decide --lasting` (with `--areas` or `--paths`) is published to `docs/cairn/decisions/` when the plan closes. `--promote` does the same for an earlier decision. A newer decision can replace an older one, and cairn links the two both ways.

`cairn recall <paths>` lists the areas, active decisions and recent closed plans that touch those paths. The session-start hook prints a short index of areas, active decisions and recent plans. It is built each time from the docs and never saved.

`cairn render` writes `OVERVIEW.md` (areas, decisions table, plan timeline) and each area's History section. `/cairn:map` surveys an existing repo once, proposes areas with path globs, drafts the docs and backfills lasting decisions from old plans.

## Gotchas

- 2026-10-27: The glob matcher has no `{a,b}` braces, so area paths list files individually.
- 2026-10-27: `--areas` and `--paths` are comma-separated with no spaces.
- 2026-10-27: Parallel plan branches conflict on `OVERVIEW.md` and History at merge. Rerun `cairn render` to resolve.
